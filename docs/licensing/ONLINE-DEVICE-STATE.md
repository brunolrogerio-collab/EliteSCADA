## State ownership and preparation

`FileOnlineLicenseStateStore` persists a **per-machine installation protocol journal**, outside Engineering and `.escadapkg`. It reuses `IProtectedMaterialAuthority` / `FileHostProtectedMaterialAuthority` (AES-256-GCM, deployment-owned external protection key). It does not create another crypto provider, Windows-only key store, or policy store. `ProtectedMaterialScope` binds owner `deployment:product-licensing`, kind `ProductLicensing`, the stable machine fingerprint, and purpose `OnlineDeviceState`.

The whole state is encrypted: Portal origin, all expected IDs, account identifier/license code, current refresh credential, pending request ID/next credential and signed lease. The host journal holds only a schema and opaque protected-material reference. Serialized cleartext bytes are zeroed after storage; secret transport strings still have normal managed-memory lifetimes. Internal state/intent classes do not generate a record ToString containing credentials. No password is persisted.

An activation generates and commits its ActivationId, RequestId and random32-byte Base64url credential before sending HTTP. It requires a confirmed license/organization/application selection from the caller. The missing Portal device-flow confirmation metadata remains [queued in #741](https://github.com/brunolrogerio-collab/EliteSCADA/issues/741#issuecomment-6442920936); this client does not derive expected IDs from unverified claims or implement that UI. Reopening a pending activation requires the same account/selection and a newly supplied password; ordinary renewal uses no password.

A renewal commits its RequestId and next credential while retaining the old credential. A retry resumes that exact intent. A successful, verified response advances the credential and clears the matching intent. A stale response cannot clear a newer intent. The unsigned response expiry is never authoritative. Normal renewal becomes due48h after a72h lease; a shorter lease becomes due at two-thirds of its lifetime, before expiry. This is a due timestamp, not a running scheduler.

## Serialization and recovery

The encrypted snapshot is stored first. A temporary opaque pointer is written with WriteThrough and Flush(flushToDisk:true), then atomically renamed over the committed pointer, following existing host reference-store discipline. A failed pointer publication leaves the earlier committed intent available for an exact retry. Encrypted orphan/older snapshots are retained in this slice; safe garbage collection/retention is still required before enabling a long-running production worker. The journal is the only selected protocol state, not an independently authoritative copy of policy.

Two separate OS file-sharing leases use FileShare.None. A short journal lease protects load/change/publication; a client operation lease spans prepare→HTTP→complete to prevent a delayed sender from replaying an older credential after another call advances the protocol. Contention fails immediately with ONLINE_LICENSE_STATE_BUSY; no polling, unbounded retry or lock held over shared SQL transactions is introduced. Lock files are retained so processes do not race over unlinked lock inodes. Process exit closes the handles. Each HA node must use its own journal and activation, even with a shared application database; this does not change HA topology or its tests.

Unreadable ciphertext, missing referenced material, wrong key/machine/origin, corrupt/unknown state, authorization failure and invalid lease fail closed; they do not silently become Demo or replace offline licenses. Administrative writes require an authenticated, allowed EngineeringModify or SystemAdmin decision supplied by the canonical authorization caller, not a special role name. No background service principal is invented here.

Every committed transition persists its observed UTC time; a later operation whose clock precedes that watermark fails before sending. Incoming authenticated issue time cannot go backwards. This protects transition/reopen paths, **not yet continuous Runtime timekeeping, replay of an entire old disk backup, VM clock/volume rollback or sudden-power-loss guarantees of every filesystem/hardware combination**. The existing protected-material authority is unchanged; host volume/key/ACL/backup operations remain deployment responsibilities. Windows inherits the protected deployment directory ACL; Unix journal files/directories are600/700. No private signing key is accessed.

## Expired response and transport

An otherwise authentic Portal response may arrive after its lease expires. The verifier now returns an additive `OnlineLeaseVerificationEvidence` with signed issue/end times for Valid or Expired, while Expired still has **no capability/quota claims**. Invalid has neither. This lets the protocol finish a credential rotation without treating an expired lease as authorization; the next renewal is already due. It does not cause the product's required future expiry-to-Demo transition.

`OnlineLicenseDeviceClient` sends the exact Portal activation/renewal fields over a pinned HTTPS origin. Its default transport has automatic redirects and cookies disabled. The refresh credential is a per-request Bearer only on renewal. Non-200 responses, malformed/duplicate/extra response fields, activation mismatch, oversized bodies and verification rejection retain the pending intent. Passwords, credentials, request/response bodies and arbitrary Portal error messages are not logged or echoed. Response bodies are bounded to24KiB. No automatic network retry is added; a later caller retries the persisted intent.
