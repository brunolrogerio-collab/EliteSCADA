- Required base: `cfd4ea9a718c3aede93a53606b3e5fd178fae2e1`
- Profile: `DRIVER_PROTOCOL`

This connector talks to a separately installed, user-operated Zigbee2MQTT bridge through the existing MQTT transport. Inventory and state are bounded and sanitized. Stable device identity uses DataSourceId plus IEEE address; a friendly name is display/routing metadata. The curated v1 state set is Boolean and Double. Event/action exposes, commissioning, network mutation, Z2M packaging, radio ownership, rich commands and physical compatibility claims are out of scope.

## Main audit follow-up: A1 and A2

- **A1 — source-observation freshness:** A TAG becomes `Good` only when payload `last_seen` is newer than the current MQTT session/bridge freshness floor. During a read or write, it must also be newer than that operation's dispatch, and its MQTT receive time must not precede dispatch. A retained message, a non-retained replay with an older `last_seen`, or a report without source freshness remains `Stale`/`Uncertain`. Writes still dispatch once and complete only from a fresh matching report; PUBACK remains transport acceptance only.
- **A2 — canonical readiness:** the readiness snapshot reports `Starting` unless the MQTT transport is connected, the bridge is online, and current inventory was reconciled. Bridge state transitions and invalid inventory clear active inventory bindings. Readiness returns to `Ready` only after successful current inventory reconciliation; an individual sleepy/offline device does not make the whole bridge unready.
- **Focused local runs:** using SDK `10.0.400`, `dotnet test tests/Scada.Drivers.Tests/Scada.Drivers.Tests.csproj --filter FullyQualifiedName~Zigbee2MqttBridgeTests -m:1 -nodeReuse:false` passed 20/20. `dotnet test tests/Scada.Drivers.Tests/Scada.Drivers.Tests.csproj --no-restore --filter 'FullyQualifiedName~EngineeringRuntimeCoordinatorTests|FullyQualifiedName~EngineeringRuntimeLifecycleFailureTests' -m:1 -nodeReuse:false` passed 12/12, and `--filter FullyQualifiedName~EngineeringRuntimeCommunicationDiagnosticsTests` passed 1/1. The latter two suites use local loopback sockets and were run with the necessary sandbox permission. These are local focused results, not the required exact-head T1.
