# EliteSCADA Asset Factory

Repository-side tooling for issue #474 / `C-BUILTIN-STATIC-ASSET-FACTORY-01`.

This tooling is intentionally **not** Runtime/Engineering authority. It prepares, validates and catalogs product-shipped static artwork without modifying `CanonicalVisualRenderer.tsx`, Engineering schema, `core.image`, `core.svgSymbol`, Canvas, Dynamo runtime composition or reusable-library semantics.

## Workflow

```text
source/batch metadata
  -> inspect provenance/license
  -> SVG lint + conservative sanitize
  -> deterministic normalization
  -> source SHA-256 + normalized SHA-256/fingerprint
  -> taxonomy/catalog validation
  -> duplicate report
  -> review candidate + deterministic thumbnail
  -> explicit human review evidence for generated/original artwork
  -> approved built-in publication output
```

### Commands

Run from repository root:

```bash
node tools/asset-pipeline/cli.mjs build --all --check-duplicates
node tools/asset-pipeline/cli.mjs build --batch assets/sources/seed/seed.batch.json --check-duplicates
node tools/asset-pipeline/cli.mjs check
node tools/asset-pipeline/cli.mjs search pump
node tools/asset-pipeline/cli.mjs search arrow --approved-only
node tools/asset-pipeline/cli.mjs scale-test --count 600
node --test tools/asset-pipeline/tests/*.test.mjs
```

To create a batch metadata skeleton for a directory of many SVGs without hand-authoring one JSON per file:

```bash
node tools/asset-pipeline/cli.mjs scaffold \
  --input assets/sources/my-batch \
  --category industrial/process/pumps \
  --out assets/sources/my-batch.batch.json \
  --author "EliteSCADA"
```

`build --all` is the only command that cleans/regenerates global candidates, thumbnails, approved built-ins and catalog/index outputs. `build --batch <file>` is intentionally validation-only: it checks one batch in isolation and never cleans or overwrites global generated outputs.

`scaffold` deliberately creates `draft` entries with `UNKNOWN` license metadata. Both `--input` and `--out` must remain under `assets/sources/`, so the generated batch is directly consumable by the same pipeline. That output is an ingest starting point, not approval.

## Repository layout

- `assets/sources/**`: source candidates + `*.batch.json` batch metadata.
- `assets/candidates/**`: deterministic sanitized/normalized review candidates generated by full `build --all`.
- `assets/thumbnails/**`: deterministic SVG review previews generated by full `build --all`.
- `assets/catalog/taxonomy.v1.json`: extensible, language-neutral category paths with localized labels.
- `assets/catalog/builtin-assets.v1.json`: generated source/catalog manifest.
- `assets/catalog/builtin-assets.index.v1.json`: generated lightweight search index.
- `assets/catalog/schemas/**`: versioned JSON Schemas for interchange/documentation.
- `assets/licenses/**`: license/provenance references.
- `assets/builtin/**`: publication output for `approved` assets only.

## Approval rule

`draft`, `rejected`, `deprecated`, `approved` are supported status values.

An `approved` item must have:

- distributable provenance classification (not `reference-only`);
- known license identifier and reference;
- explicit `commercialRedistributionAllowed: true`;
- modification permission when the item is `derived-permitted`;
- explicit review evidence (`reviewedBy`, `reviewedAt`, `reviewNote`) when provenance is `generated/original`.

This prevents generated artwork from becoming product-shipped merely because an automated build succeeded.

## SVG safety model

SVG input is treated as untrusted text. The first version intentionally accepts a conservative static subset.

Rejected:

- `<script>`;
- event attributes (`onload`, `onclick`, etc.);
- `foreignObject`;
- `<style>`, `<image>`, `<a>`, iframe/object/embed content;
- `javascript:`, data/file/http/https/ftp resources;
- non-fragment `href`;
- external `url(...)` paint/resource references;
- DTD/entities, processing instructions and CDATA;
- non-whitespace text nodes;
- malformed/unbalanced tags;
- unquoted/unknown attributes;
- duplicate IDs;
- SVG > 256 KiB;
- >10,000 tags;
- extreme `viewBox` dimensions;
- excessive path-data length.

Preserved when safe:

- `viewBox`;
- paths/basic geometry;
- groups/defs/transforms;
- fill/stroke/opacity;
- linear/radial gradients and geometric hatch patterns with internal references;
- clip paths and masks within the accepted static subset;
- inert `data-elitescada-slot` metadata.

Not yet supported deliberately: text/font nodes, filters, markers, embedded raster images, CSS/style blocks, animation/SMIL, external resources and arbitrary SVG DOM features. Unsupported constructs fail explicitly instead of being silently executed or injected.

## Normalization and dedupe

Normalization strips comments/fixed root dimensions, canonicalizes `viewBox`, assigns deterministic internal IDs (`a1`, `a2`, ...), rewrites internal fragment references and sorts attributes. It does not rewrite geometry merely for cosmetic standardization.

The catalog records:

- `sourceSha256`: exact source bytes;
- `sha256`: sanitized/normalized bytes;
- `normalizedFingerprint`: canonical normalized-vector fingerprint (currently SHA-256 of normalized SVG).

Duplicate detection reports exact source duplicates, normalized duplicates and conflicting metadata for the same source URL. It never deletes or merges non-identical assets automatically.

## Seed policy

The initial seed spans Industrial, P&ID, Sanitation, Electrical, Building, Residential, Navigation, UI/HMI, Indicators and Flow/Connectors. It exists to prove the factory, not to be the final library.

All seed artwork is marked `generated/original` and remains `draft` pending Main visual review. No third-party artwork bytes are included in this seed.
