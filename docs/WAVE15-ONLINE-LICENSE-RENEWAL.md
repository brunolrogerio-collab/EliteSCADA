## Delegation rather than an administrator impersonation

An administrator-authorized activation/reauthentication response, verified and committed by `FileOnlineLicenseStateStore.CompleteAsync`, now grants host maintenance for that ActivationId in the encrypted journal. Internal snapshot schema3 reads1/2; older records without this grant cannot automatically renew. An explicit administrative operation must establish the new delegation. Reset clears both the grant and attempt timestamp. No role, workspace policy or login password is persisted for maintenance.

The host context is internal and bound to the exact ProductLicensing/machine/OnlineDeviceState scope and ActivationId. Its principal is not an authenticated interactive user and its ordinary authorization decision is denied. Generic `DemandAuthorized()` rejects it. Only the scoped protected-material authority path accepts it for the exact scope. Journal renewal/completion/rejection/pacing/retention additionally checks the persisted activation delegation. Activation, new login, reset and other protected resource scopes still require ordinary administration. This is a trusted in-process maintenance capability, not an API bearer credential or permission to other product operations. Audit names the host maintenance actor, scope and activation instead of claiming an interactive EngineeringModify grant.

## One serialized protocol-to-entitlement operation

`OnlineLicenseDeviceOrchestrator` holds the existing cross-process journal operation lease through prepare → HTTP → response persistence → canonical lifecycle application. Existing direct client/store operations retain their locking; internal `WhileOwned` paths are only for an owner already holding this lease. No SQL transaction is held during HTTP. Offline install/remove uses the same lease when the device journal is configured, so a concurrent mode change/reset fails explicitly rather than racing a delayed response. The independent expiry guard never waits for this lease and remains able to reduce rights at the signed deadline.

The worker reads only the selected online installation. A journal alone cannot activate online mode, and an offline/removal selection is not replaced automatically. Binding and installation CAS remain enforced by the lifecycle. If the independent guard expires an old lease while HTTP runs, a newly signed valid response can renew that same activation using its current revision. A failed response application leaves the committed journal response available; the next pass applies it before sending another credential rotation. Explicit activation retry can likewise apply an already committed matching response without sending the password again or advancing an already-selected epoch. Reauthentication retries preserve the same activation/confirmed identities.

Local reset first removes canonical rights through lifecycle/fencing, then commits the encrypted tombstone and clears delegation. A reset interrupted after removal can be completed explicitly against the same journal; absent selection never triggers automatic reactivation. Reset is idempotent locally, audited with its activation/epochs, and does not revoke/free a Portal slot. The public endpoint/UX still has to explain that distinction.

## Scheduling, pacing and retention

`OnlineLicenseRenewalHostedService` checks every30s. Normal renewal is due48h after issue; a short lease is due at two thirds of its signed lifetime. Before an HTTP attempt, the encrypted journal commits a next-attempt floor of five minutes. It survives restart and response loss, bounding automatic retries instead of issuing a request on every worker iteration. The Portal request/next credential remain exactly the persisted pending intent. Each HTTP operation has a20s product timeout independent of the expiry guard; no existing test/CI timeout is changed.

Pacing persists across maintenance completion until a later due time or explicit administrative reauthentication. Rejection401/403 durably disables further automatic sends until a new login; the current authentic lease remains usable only until its signed deadline. Portal errors never select another license or replay a user password. Malformed/expired responses remain subject to the real verifier and protocol completion rules, without receiving capabilities from unsigned metadata.

Before each paced attempt and after successful application, retention removes at most128 obsolete same-scope ciphertext snapshots through the existing authenticated-anchor collector. The selected reference survives; another resource/machine is untouched. Network outages therefore do not accumulate an unlimited snapshot chain solely from retries. Initial orphan/no-readable-anchor recovery remains the conservative limitation documented for #798.

Renewal outcome audit uses the canonical store with activation/correlation and bounded result code, never request/response bodies or credentials. Failure after a successful canonical change may leave a missing transport-outcome receipt; the mandatory lifecycle audit remains separately required before Complete. Delivery is not exactly once, and journal/file/SQL publication are reconciled rather than claimed to be one atomic filesystem/database transaction.

## Opt-in composition and validation

Configure `Licensing:Online:PortalOrigin` only for the intended HTTPS Portal origin, without user info/path/query/fragment. `Licensing:Online:StateDirectory` optionally chooses the host-owned persisted directory; the default is `data/licensing/online` under the API base directory. The existing protected-material key/volume and stable machine identity are required. No origin means no device client/orchestrator/renewal-worker registration; the independent local expiry guard remains registered. This configuration neither changes Portal signing nor activates a license. Each HA node needs its own stable identity, journal and activation; the shared application database is not a shared online-device identity.
