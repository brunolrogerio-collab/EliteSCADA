## One selected entitlement source

`FileProductLicenseService` remains the `IProductLicenseService` resolved by production DI. Its existing machine-license path selects one mode at a time. Offline ESLIC1/2/3 parsing and verification are unchanged. The online branch reads an internal `SCADIVO-ONLINE-INSTALLATION1` descriptor (schema 1): expected binding, signed ESLEASE1 envelope, random CAS revision, last-observed UTC and whether expiry was explicitly applied. No password, refresh credential, private key or policy is stored there. Expected identities come from the confirmed journal binding, not claims decoded from an unsigned response.

The descriptor is installation state, not a new publicly importable license format. `VerifyCandidate`/`InstallLicense` continue to reject ESLEASE1 and the internal descriptor. Older binaries fail closed on this mode. The transport journal remains encrypted and owns credential/request rotation. `ReadEntitlementCandidateAsync` produces only a bound, currently verified candidate; completing HTTP/journal publication alone does not select it as Runtime authority.

All online reads reverify against the dedicated pinned public key. There is no configurable online-key override. Tests use an internal seam and ephemeral RSA3072 key, executing the real verifier. Valid signed totals/flags project into existing entitlement contracts so Run, session admission, HA and Intelligence share the same canonical result. The projection is not an offline ESLIC artifact. Quotas are effective totals, not additions to Demo pools. An invalid signature/binding/machine/schema or premature expiry marker remains Invalid; it cannot become Demo.

## Reuse the existing authority transition

Internal lifecycle operations `InstallOnlineAsync`, `RenewOnlineAsync` and `ExpireOnlineAsync` reuse `ProductLicenseLifecycleCoordinator.ChangeAsync` and the existing lease store. There is no parallel SQL epoch or lock: Begin pending → replace canonical installation file → commit authority revision → re-evaluate local Run → fence older leases → Complete. Pending denies lease use and concurrent authority mutation. Cancellation after file publication cannot abandon this safety sequence. Startup `ReconcilePendingAsync` uses the selected canonical artifact after interruption; unreadable state does not grant online capabilities.

Online renewal requires the expected installation revision and identical license/organization/application/activation/machine binding, with nondecreasing signed issue time. File CAS prevents late responses from replacing a later online lease or an explicit offline/removal selection. An explicit new online selection uses the separate install operation. The previous offline license is not an automatic fallback. Every applied online renewal conservatively advances the epoch and fences existing sessions; optimizing unchanged-claim renewal is not part of this slice.

The future device orchestrator must serialize journal completion/candidate publication with reset and selection changes, reusing the journal's existing operation lease. The internal candidate itself is not a permission, a remote revocation check or a transaction spanning HTTP/journal/installation. A successful device response followed by failed lifecycle application must remain retryable from the journal. This caller integration is still a required gate before exposing activation/reset or starting the worker.

At `now >= NotAfterUtc`, reads return Invalid/`ONLINE_LICENSE_EXPIRY_TRANSITION_REQUIRED` until the coordinated expiry operation runs. That operation accepts only a still-authentic expired lease, writes the durable expiry marker and re-evaluates the whole Run under Demo: up to 200 definitions may continue without a timer; 201 or more stops the Run, without discarding a subset. HA/Intelligence and old Runtime sessions lose commercial entitlement through the existing canonical gates. Repeating an already completed expiry does not advance the epoch again. Explicit removal still clears an expired online selection; ordinary absent Demo removal remains idempotent. Invalid/expired offline licenses never use online fallback.

## Definition count correction

The new real-runtime tests exposed that authority re-evaluation used the materialized server registry count, while activation checked `package.Tags.Count`. An accepted package with 201 disconnected or client-only definitions could therefore be re-evaluated as below the Demo ceiling. `ProductLicensedRuntimeCoordinator` now retains the accepted Engineering definition count after successful activation/materialization and uses it during re-evaluation. Failed candidate activation does not replace that count. This corrects the licensed unit; it does not change driver acquisition, HA protocols or Engineering content. Both materialized and disconnected 200/201 cases are tested.

## Persistence and time

Writes use the same canonical path, random temporary filename, WriteThrough/Flush and atomic replacement. A retained OS file-sharing lease serializes offline/online/removal/checkpoint writes across processes sharing that installation file. This is local file ownership, not another distributed-authority lock. SQL authority serialization remains in the existing lease store. Unix installed files are 600; Windows retains deployment directory ACL responsibility.

Effective online time never goes below the selected persisted watermark or elapsed monotonic time observed in this process. A stopped/backward wall clock cannot extend the remaining lifetime within a running process. `CheckpointOnlineClock(expectedRevision)` persists the observed floor without changing entitlements or the CAS revision. A reopened process whose UTC is behind that saved floor fails closed with `ONLINE_LICENSE_CLOCK_ROLLBACK`; it does not grant another remaining-lifetime window because elapsed downtime is unknowable. Reads may resume when UTC catches up to the saved evidence. It does not claim protection against rollback of an entire disk/VM/backup. Deployment clock/volume integrity and periodic checkpoint scheduling remain required.
