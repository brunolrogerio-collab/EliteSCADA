# EliteSCADA Offline License Operations

Status: Preview/Demo product gate

This document defines the operational boundary for generating and installing EliteSCADA licenses. Production private signing material must stay outside the repository, normal CI, customer packages and the EliteSCADA runtime host.

## 1. Create the signing key pair offline

Create the key pair on a controlled offline workstation. One supported OpenSSL flow is:

```bash
openssl genpkey -algorithm RSA -pkeyopt rsa_keygen_bits:3072 -out elitescada-license-private.pem
openssl pkey -in elitescada-license-private.pem -pubout -out elitescada-license-public.pem
```

Treat `elitescada-license-private.pem` as a production secret. Back it up according to the company's secret-management process. Never add it to Git, CI variables, customer installers or support tickets.

The public file may be deployed with EliteSCADA runtime installations.

## 2. Configure the runtime verification key

The runtime loads public verification keys from configuration. Example:

```json
{
  "Licensing": {
    "LicenseFile": "data/licensing/EliteSCADA.license",
    "VerificationKeys": {
      "preview-1": "data/licensing/elitescada-license-public.pem"
    }
  }
}
```

`preview-1` is the key identifier embedded in licenses generated by the Preview License Generator. Future key rotation can add a new identifier while retaining an older public key for already-issued licenses.

## 3. Obtain the machine request

On the target EliteSCADA host, read:

```text
GET /api/licensing/request
```

The response contains a versioned `ESREQ1...` request code and the SHA-256 machine fingerprint. The request code contains no private signing material.

## 4. Generate a license offline

Copy only the machine request code to the controlled licensing workstation. Use the published Windows x64 executable:

```powershell
EliteSCADA.LicenseGenerator.exe `
  --request "ESREQ1..." `
  --tier 1000 `
  --key "D:\EliteSCADA-Secrets\elitescada-license-private.pem" `
  --key-id preview-1 `
  --out "EliteSCADA.license"
```

Supported tiers:

- `500`
- `1000`
- `1500`
- `3000`
- `5000`
- `Unlimited`

Optional expiration:

```powershell
--expires "2027-08-31T23:59:59Z"
```

The generator fails closed if the request, tier or private signing material is invalid.

## 5. Install the license

The product API accepts a license only after signature, key-id, hardware binding and validity checks pass:

```text
POST /api/licensing/install
```

Body:

```json
{
  "licenseCode": "ESLIC1..."
}
```

An invalid API installation is rejected and does not replace the current license file. If a license file is externally corrupted or replaced after installation, runtime verification reports `Invalid` and subsequent Run activation is blocked rather than silently falling back to Demo.

## 6. Demo behavior

When no license file is installed:

- Engineering remains unrestricted by the Demo 200-TAG limit;
- Run is allowed only for projects with up to 200 TAGs;
- each explicit successful Demo Run starts a fresh 300-minute continuous session;
- expiry stops the active runtime gracefully and leaves Engineering intact;
- a later explicit Run starts a new Demo session.

## 7. Licensed behavior

A valid signed license applies its configured TAG tier. Licensed Run has no Demo 300-minute timeout. `Unlimited` has no TAG capacity ceiling.

## 8. Key rotation

To rotate signing keys:

1. generate a new offline key pair;
2. deploy the new public key alongside the previous public key;
3. configure a new `key-id`, for example `preview-2`;
4. begin issuing new licenses with that id;
5. keep old public verification keys while licenses signed by them remain supported.

Private keys are never required by the EliteSCADA runtime.
